# 混沌 HunDun

> 一个从零自研的操作系统与其配套语言。
>
> **Windows `\` 一切皆注册表 · Unix `/` 一切皆文件 · 混沌 `^` 一切皆哈希**

从引导扇区到命令行提示符，全是自己写的：引导器、语言、编译器、盘格式、
压缩、ATA 驱动、帧缓冲控制台、内容寻址对象存储。

**没有一行取自 Linux，也没有链接任何现成内核。**

```
内核 60 KB  ·  最底层汇编只剩 1296 字节  ·  13 个可拆模块
```

## 一分钟看它在干什么

开机进命令行，敲几条命令，你会看到这些东西：

```
HD> cun hello
  已存 → 哈希 4f9f2cab   （1335831723）

HD> cun hello
  已存 → 哈希 4f9f2cab   （1335831723）     ← 一模一样

HD> pan
  格式版本 1   世代 3
  对象数 2   追加指针 LBA 22   索引起 LBA 3

HD> qu 4f9f2cab
  「hello」
```

**同一个内容存两次，哈希一模一样，盘上只占一份。**

然后关掉虚拟机、重新开机：

```
HD> qu 4f9f2cab
  「hello」
```

东西还在。不是"保存到文件"，是**对象已经在盘上了**。

还有一条命令看这台机器：

```
HD> xin
                            系统    混沌 HunDun OS
        ░░░░░               内核    自研引导器 xboot + 新语内核
      ░▒▒▒▒▒▒▒░             语言    新语（关键字全拼音，危险操作要 wx{}）
     ░▒▓▓▓▓▓▓▓▒░            固件    SeaBIOS
    ░▒▓███████▓▒░           处理器  GenuineIntel · 1 核
    ░▒▓█▒▒▒▒▒█▓▒░           显卡    QEMU / Bochs 标准 VGA
    ░▒▓█▓███▒█▓▒░           内存    255 MB
     ░▒▓▓▓▓▓▓▓▒░            显示    1920 x 1080 x 32 位  帧缓冲 0xfd000000
      ░▒▒▒▒▒▒▒░             盘      混沌盘 v1  8 MB  0 个对象
        ░░░░░               网络    （还没有网络栈，所以没有 IP）
                            一切皆哈希 · 内容寻址 · 只追加
```

**左边那个漩涡不用汉字画** —— `░▒▓█` 三级阴影从外到内由疏变密，
核心故意不圆（还没分化出形状）。那就是"混沌"。

右边每一项**都是真去问硬件的**，不是写死的：

| 项 | 数据从哪来 |
|---|---|
| 处理器 | **CPUID 指令**（0x80000002-4 拿型号串，0 拿厂商） |
| 核数 | **ACPI 的 MADT 表**（RSDP → RSDT → 找 "APIC" → 数处理器记录） |
| 显卡 | **PCI 配置空间**（扫类代码 0x03 的设备） |
| 固件 | **SMBIOS type 0** 的字符串 |
| 内存 | BIOS E801 |
| 显示 | VBE 模式信息 |
| 盘 | 混沌盘超级块 |

## 怎么跑起来

### 依赖

只要三样：

```
clang           编编译器本身（xyc.c）
binutils        as / ld / objcopy（最后一步汇编链接）
python3         打包工具（xiso.py 等）
```

可选：`qemu-system-i386` 用来跑。

### 构建

```sh
git clone <这个仓库>
cd hundun

sh 构建/构建.sh 终端 混沌终端.iso      # 命令行版
sh 构建/构建.sh 桌面 混沌桌面.iso      # 图形桌面版
```

出来的 ISO 可以直接给 QEMU / VirtualBox / VMware 用。

### 运行

```sh
qemu-system-i386 -cdrom 混沌终端.iso -boot d -m 256 -vga std
```

**注意两点：**

- `-vga std` 要给 —— 终端是画在帧缓冲上的（见下面"为什么要帧缓冲"）
- 虚拟机要用 **BIOS 引导，不要 UEFI**（VirtualBox 别勾 EFI，Hyper-V 必须第 1 代）

想能存东西就再加一个盘（没有也能开机，只是不能存）：

```sh
qemu-system-i386 -cdrom 混沌终端.iso -boot d -m 256 -vga std -hda 混沌盘.img
```

空白盘会被自动格式化，随便造一个就行。

### 为什么要帧缓冲

本来想做纯文本模式终端，撞到一个硬问题：

> **VGA 文本模式每个字符格子只有 1 个字节**，UTF-8 一个汉字 3 字节，塞不进去。

所以终端**自己在帧缓冲上画字**：800×600×32 显存 + 自研点阵字库 + 自己管光标和滚屏。
代价是滚屏要用汇编做（新语逐像素搬太慢）—— 这是"内核里那块汇编"存在的原因之一。

分辨率不写死：引导器会**优先挑 1920×1080，拿不到就挑能拿到的最大那个**，
桌面排版全部按实际分辨率算。

## 编译器怎么用

编译器叫 `xyc`，输入新语源码，输出 i386 汇编。

### 四种模式

```sh
xyc 源文件.xy -o 输出.s            # 默认：完整程序（含入口 _start 和运行时）
xyc -c 模块.xy -o 模块.s           # 模块：不出入口、不出运行时、函数导出
xyc -m 主模块.xy -o 主.s           # 主模块：出入口、不出运行时
xyc -r 空文件.xy -o 运行时.s        # 只出运行时（_rt_* 和内核栈）
```

外加一个开关：

```sh
-nx                                # 不生成 Multiboot 头（自研引导器路线用）
```

### 为什么要分四种模式

因为内核**是可以拆的**。

一个 `.xy` 文件天生会自带两样东西：程序入口 `_start`、以及运行时（`_rt_putc` 那些）。
两个文件链在一起就会**入口重定义**、**运行时重复**。

所以：

```
运行时.o      ← xyc -r，全程序只此一份
主模块.o      ← xyc -m，唯一带 _start 的
其它模块.o    ← xyc -c，想要几个要几个
```

想砍掉哪块，**从链接命令行删掉就行** —— 它在内核里就不存在，
不是"配置项关掉"，是**从未编进去**。

### 全局变量怎么跨模块共享

新语没有 `extern`，所以模块里的全局用 `.comm` 声明：

```c
.comm g_对象哈希, 64, 4
```

**链接器会保证同名全局合并成一份。** 这就是"对象区在整个内核里只有一份"的物理保证 ——
不管多少个模块在用它，内存里只有一个。

### 一个例子

```sh
# 1. 编运行时（全程序一份）
xyc -r /dev/null -o 运行时.s

# 2. 编两个模块
xyc -c 模块甲.xy -o 甲.s
xyc -c 模块乙.xy -o 乙.s

# 3. 编主模块
xyc -m 主.xy -o 主.s

# 4. 汇编、链接
as --32 运行时.s -o 运行时.o
as --32 甲.s    -o 甲.o
as --32 乙.s    -o 乙.o
as --32 主.s    -o 主.o
ld -m elf_i386 -T 链接/link_xboot.ld -o kernel.elf 运行时.o 甲.o 乙.o 主.o
```

（`构建/构建.sh` 把这些串好了，实际不用手敲。）

## 内核怎么组织的

```
运行时.o     2128   xyc -r      _rt_* + 内核栈，全程序一份
内核对象.o   7996   xyc -c      对象区（内容寻址）
界面.o      21492   xyc -c      混沌UI + 绘图基元 + 部件
应用.o      20672   xyc -c      四个应用 + 对象区窗口
盘.o         4032   xyc -c      ATA PIO 驱动（纯新语）
盘格式.o    10516   xyc -c      混沌盘：超级块 / 对象区 / 索引区 / 轴区
压缩.o       7160   xyc -c      LZSS（译自 0BSD 源码）
机器.o       8547   xyc -c      CPUID / SMBIOS / PCI 探测
壳.o        18343   xyc -c      命令行壳
主.o         6540   xyc -m      唯一带 _start 的
图形.o       7820   汇编         帧缓冲 / 鼠标 / 键盘
原语.o       1296   汇编         端口 + 内存 + CPUID + 停机
字体.o      21708   生成         点阵字库
boot1.o boot2.o      汇编         自研引导器
```

### 最底下那一层

**整个内核里只有 `原语.asm` 是汇编**，1296 字节的目标文件，只干六件事：

```
端入 / 端出       读写 I/O 端口
端入字 / 端出字    读写 16 位端口
端入32 / 端出32    读写 32 位端口（PCI 要用）
读32 / 写32       按 32 位读写任意内存
读8 / 写8         按字节读写任意内存
读CPUID           执行 CPUID
停机
```

**上面所有东西 —— 图形、文字、鼠标、键盘、对象区、应用、桌面、磁盘驱动 —— 都用新语写。**

### 引导链

```
固件
 → boot1.asm   (512 字节 El Torito 引导扇区)
     · 段寄存器全部归零，之后一律用线性地址
     · 存下引导盘号，跳到第二阶段
 → boot2.asm   (紧跟其后，一次性载入)
     · 打开 A20
     · 取内存大小（E801）
     · 用 BIOS 扩展读从光盘把内核读进 0x10000
     · 找并设置 VBE 模式（优先 1920×1080）
     · 建 GDT，进 32 位保护模式
     · 填 XBP 引导信息块，交棒
 → 内核
```

**XBP 是自研的引导协议**（不是 Multiboot）：EAX = 魔数，EBX = 信息块地址。

### 盘格式：混沌盘

不是文件系统，是**内容寻址的对象存储 + 一条单调轴**。

```
LBA 0        超级块 A          ┐ 双超级块，写时 A/B 交替
LBA 1        超级块 B          ┘ 读时选【世代号大的】那一块
LBA 2        视图记录区
LBA 3..18    索引区            哈希 → 扇区号
LBA 19..     对象区（只追加）    魔数 OBJ / 类型 / 长度 / 哈希 / 内容 / 扇区自校验
LBA 4096..   轴区（只增不减）
```

**为什么是图不是树**：树必须有一个根，而设计里没有全局根（公理 3）；
"就地修改"会毁掉历史，而设计里对象不可变（公理 1）。所以盘格式只能是图。

## 新语速查

> 完整版见 [`文档/新语速查.md`](文档/新语速查.md)

### 关键字（全拼音缩写）

```
hs  函数        fh  返回        bl  不可变绑定    kb  可变绑定
rg  如果        bz  不然        dy  条件循环      xh  无限循环
tc  跳出        jx  继续        qj  全局          jg  结构体
wx  危险块      @   注释
```

### 注释是 `@`

```c
@ 这是注释
# 这也是（旧版符号，兼容保留）
```

### 核心设计：**危险要签字**

```
bl x = 1        不可变绑定
x = 2           ← 编译错误：不可变绑定不可赋值（要可变请用 kb）

bl p: *u8 = "ABC"
kb c: u32 = ^p  ← 编译错误：解引用原始指针是危险操作，必须写在 wx { } 里
wx { c = ^p }   ← 这样才行
```

编译器还会**统计你开了几个危险块**：

```
xyc: 新语 stage0 v0.4 -> 输出.s（2 字符串 / 0 全局 / 1 函数）
     危险统计：wx 危险块 1 个，原始指针操作 1 处
```

这个设计的意思是：**默认安全，危险的动作要你亲手签字。**
不是限制你，是让危险在代码里显形 —— 你一眼就能数出一个文件里有几处可能出事。

### 内建

```c
@ 输出
印("字符串")          字符串（只能是字面量，见下）
印(变量)              数字
印串(指针)            把指针当字符串打
出(字节)              输出一个字节（屏幕 + 串口）

@ 图形
绘点(色×y×x) 绘块 绘框 绘字 绘数 绘十六 绘块混 取点 滚屏
屏宽() 屏高() 帧址() 行宽() 内存()

@ 输入
键() 鼠x() 鼠y() 鼠钮() 轮询() 时() 分() 秒() 睡(毫秒)

@ 机器原语
端入 端出 端入字 端出字 端入32 端出32 读32 写32 读8 写8 读CPUID 停机
```

### 几个必须知道的坑

| 坑 | 说明 |
|---|---|
| **`印(变量)` 打的是数字** | 编译器看参数是字面量还是变量决定调 `_rt_puts` 还是 `_rt_puti`。要打变量里的字符串得用 `印串(指针)` |
| **数组槽是 32 位** | `取回[i] = 230` 写的是 4 字节（`E6 00 00 00`）。当字节数组用**必须走指针写**：`wx { ^(地址 + i) = v }` |
| **函数参数不可变** | 要改先 `kb 局部 = 参数` |
| **一个函数一个作用域** | 多个 `rg` 分支里各写 `kb x` 会报"已经绑定过了"，要提到函数顶部 |
| **`bz` 要跟 `}` 同一行** | `rg a { } bz { }` 换行写会解析失败 |
| **`z` 是个类型** | 1 字节类型，不能当变量名 |
| **`dy` 是关键字** | 条件循环，不能当变量名 |
| **参数压栈是从左到右** | 所以进入被调函数时**第一个参数在更深的位置**（`[esp+4n]`）—— 写汇编运行时时最容易搞错的地方 |

## 现在做到哪了

✅ = 已实现并实测    🔧 = 有设计没实现    ❌ = 没做

| 层 | 状态 |
|---|---|
| 硬件 / 引导器 / XBP 协议 | ✅ 自研引导器实测能起，1920×1080 |
| 块设备 | ✅ ATA PIO（纯新语） |
| 混沌盘 | 🔧 布局有了，能写能读能校验、重启还在；索引还是扁平表、轴区没做实 |
| 对象（内容寻址） | ✅ 去重 + 哈希校验（内存版 + 盘上版） |
| 能力（存/取/列/映射/撤销） | 🔧 五条通了；"视图""跨越"还没做实 |
| 分身 | ❌ 只有设计文档 |
| 视图 | ❌ 盘上留了位置，没做实 |
| 包格式 `.bao` | ❌ 没做 |
| GC / 墓碑 / 世代折叠 | ❌ 没做 |
| 调度器 / 多核 | ❌ **故意的**，见 [`文档/`](文档/) |

### 已知问题

- **SMBIOS type 1（机器品牌/型号）读不出来**：结构链从结构 0 走到 1 会走飞。
  type 0（固件）能读对，说明查表和取串是好的，问题在"往下走一个结构"。
  这块暂时从 `xin` 输出里去掉。
- **网络**：没有网络栈，所以没有 IP。

### 为什么没有调度器

因为**还没有"要被调度的东西"**。

常规系统调度的东西叫进程；这里没有进程，有的是**分身** —— 而分身的"上下文"就是一个引用。
设计规范里的公理 7 写的是：

> **视图切换是单一原子动作。**

**这句话本身就是"换用户上下文"的意思。**

所以：**先把视图做实，调度器是自然结果；反过来先写调度器，调度的就是空气。**
（详见 [`文档/`](文档/) 里的讨论）

## 路线

把外部依赖一层层换掉，从下往上：

```
✅ 自研 ISO 9660 + El Torito 打包器（换掉 xorriso）
✅ 自研引导器 + 自研引导协议（换掉 isolinux + Multiboot）
🔧 自研汇编器 / 链接器 / 内核格式（换掉 as / ld / ELF）
❌ 视图做实 → 多环境 + GC 的地基
❌ .bao 包格式
❌ 自举：用新语重写编译器自己
```
