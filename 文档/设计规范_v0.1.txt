零、定位（第一句话，对外发布的原文）
────────────────────────────────────────────────────────────────

  > 这是一个从零构建的、不可约化的视图式对象系统与其配套语言。
  > 它不取代任何现有系统，也不承诺兼容任何现有系统。
  > 它的目标是让读者换一套大脑，而不是换一套命令。

  三条禁令（写给自己看的，防止滑回旧世界）：
    · 禁止用"兼容 Linux/Windows"作为卖点
    · 禁止出现"以后再补"的空壳子系统（框架在、功能空的，一律删掉）
    · 禁止在文档里出现"吊打""碾压"类措辞

────────────────────────────────────────────────────────────────
一、世界观公理（七条，不可删改）
────────────────────────────────────────────────────────────────

  公理 1  不可变：一切对象一经产生，永不改变。变更 = 产生新对象。
  公理 2  内容即身份：对象的名字是它内容的哈希。哈希相同即同一个对象。
  公理 3  无全局根：系统不存在唯一的命名空间根。名字只相对于"锚点"有意义。
  公理 4  视图：一个执行体可见的一切 = 它持有的锚点集合 + 每个锚点提供的映射。
  公理 5  能力即引用：访问某对象的唯一途径是持有指向它的引用。
          不存在"路径字符串绕过引用"这种可能性。
  公理 6  映射即对象：名字到引用的映射表本身也是对象，因此可寻址、可版本化。
  公理 7  变更原子：视图切换是单一原子动作（换一个映射引用）。

  这七条中删掉任何一条，都会导致至少一条断言（见第八节）失败。
  这是"不可约化"的可操作定义。

────────────────────────────────────────────────────────────────
二、符号体系（键盘身份）
────────────────────────────────────────────────────────────────

  核心思想：符号不是装饰，每一个都承担语义。同族符号用"重复次数"表达
  语义强度，形成体系感 —— 这是让人"从零学但不觉得随意"的关键。

  ── 2.1 命名与视图符号 ──────────────────────────────────────

    ^         引用跳转：在锚点提供的映射里查这个名字（一次能力跨越）
    ^^        不主动列出（视图展示策略：仅显式请求时出现）
    ^^^       不主动列出，且禁止跨视图引用（最内层）
    ~         锚点回退：回到上一层锚点（替代 Unix 的 ..）
    @         当前视图锚点（替代 Unix 的 .）

    语法示例：
      系统^配置^网络        从「系统」出发，两跳取到网络
      @^报告                 当前视图里的报告
      ~^文档                 回到上一层锚点，再取其下的文档
      ^^本机密钥             隐藏：默认列出时不显示
      ^^^内部表             隐藏且禁止跨视图引用

    ★ 与 Unix 的根本差别：
      Unix 的 / 隐含"存在一个根"，^ 不隐含任何根。
      每个 ^ 都是一次可失败、可审计、可撤销的能力跨越。

  ── 2.2 语言符号 ────────────────────────────────────────────

    .         成员访问（结构体字段、对象方法）
    :         类型标注
    ->        返回类型
    *         指针（但见第四节 4.7：指针自带出处，不是裸地址）
    !         效果标记：标注"这个函数/这次调用有副作用"
    ?         可选（未定值）
    #         模块级声明/批注

  ── 2.3 释放出来的符号（Unix 用、我们重新分配）──────────────

    /         不用于命名。可用于整除运算（与 Unix 路径语义无关）
    \         完全不用。它是 DOS 的历史事故产物
    .         不再表示"隐藏"，也不再表示"扩展名"
              → 隐藏改用 ^^
              → 扩展名取消（对象自带类型标签）

三、关键字体系（新语）
────────────────────────────────────────────────────────────────

  规则：全部拼音缩写；优先两字母；冲突时用三字母或换词根。

  ── 3.1 已定 ────────────────────────────────────────────────

    hs   hánshù     定义函数
    fh   fǎnhuí     返回
    bl   biàndìng   不可变绑定（注意：是"绑定"不是"赋值"）
    kb   kěbiàn     可变绑定
    jc   jiěchú     解除绑定（从视图移除名字；对象本身不移除）
    rg   rúguǒ      如果
    bz   bùrán      不然（替代 fz，避免与"复制"冲突）
    xh   xúnhuán    无限循环
    dy   dāng…      条件循环
    tc   tiàochū    跳出
    jx   jìxù       继续
    jg   jiégòu     结构体
    mk   mókuài     模块
    wb   wàibù      外部声明
    nl   nèilián    内联汇编
    bd   bǎngdìng   绑定别名（两个名字指向同一对象）
    fz   fùzhì      复制对象（产生真正的新对象）
    z    zhēn       真
    j    jiǎ        假
    k    kōng       空

  ── 3.2 类型 ────────────────────────────────────────────────

    u8 u16 u32 u64 i8 i16 i32 i64 z
    z = 布尔（真/假）

  ── 3.3 已解决的冲突记录（保留此表，防止后人再撞）

    · 否则(fǒuzé)=fz 与 复制(fùzhì)=fz 冲突 → 否则改用 bz（不然）
    · 块(kài)=k 与 空(kōng)=k 冲突 → 不进关键字表，用 {} 表达

────────────────────────────────────────────────────────────────
四、语义反转清单（本系统的核心资产）
────────────────────────────────────────────────────────────────

  设计原则：外壳熟悉，语义反转。
  读者（和 AI）会用旧经验预测，然后全部预测失败 —— 这就是"深层懵逼"。

  ── 4.1 绑定 ≠ 赋值 ────────────────────────────────────────

    bl x: u32 = 1      # 不可变绑定
    x = 2              # ★ 编译错误：bl 绑定的名字不可再赋值

    kb y: u32 = 1      # 可变绑定
    y = 2              # 合法

    熟悉：看起来像 C 的变量声明与赋值
    反转：= 的含义由声明关键字决定；默认不可变

  ── 4.2 没有"删除"，只有"解绑" ────────────────────────────

    jc 报告            # 从视图移除名字"报告"
    # 对象仍在存储中。只要还有别的引用（或历史视图指向它），它就不消失

    反转：用户以为删除了数据，实际只是断开了自己的那一根引用

  ── 4.3 没有"权限不足"这个错误 ────────────────────────────

    你没有能力引用的名字，在你的视图里**根本不存在**。
    错误种类只有三种：

      名字不存在      你视图里没有这个名字
      能力已撤销      曾经有，被撤销了
      锚点不可达      那一跳的起点没了

    反转：Unix/Windows 会礼貌地告诉你"权限不足"，从而暴露了"存在某物"这个事实
          —— 信息泄露。本系统不泄露。你不能探测你看不到的东西。

  ── 4.4 没有"隐藏文件"，只有"展示策略" ───────────────────

    ^^本机密钥          # 名字是"本机密钥"，^^ 是视图对它的展示策略

    反转：Unix 把隐藏塞进名字里（.foo）；本系统把隐藏放在视图里

  ── 4.5 没有"扩展名" ──────────────────────────────────────

    对象自带类型标签，因此 报告 就是 报告，不需要 报告.txt

    反转：这一个改动会连锁影响 shell 补全、图标、打开方式 —— 全部改由类型标签驱动

  ── 4.6 没有"复制粘贴"，只有"绑定"与"复制"两件事 ─────────

    bd 甲 = 乙         # 绑定别名：甲乙指向同一对象（零拷贝）
    fz 丙 = 甲         # 复制：产生内容相同的新对象

    反转：用户以为的"复制"在旧系统里既可能是别名也可能是真拷贝，
          这里必须显式区分，编译器会问你要哪一个

  ── 4.7 指针自带出处（无裸指针）────────────────────────────

    一个指针不是裸地址，它携带"属于哪个地址空间/视图"这一信息。

    反转：跨地址空间使用指针 → 立即错误（编译期或运行期）
          这是把能力思想落到指针层面
    【诚实标注】硬件级能力指针的先例是 CHERI / ARM Morello。
                本系统做在语言与内核层，不依赖特殊硬件。

  ── 4.8 整数无隐式转换 ────────────────────────────────────

    u32 + u64    → 编译错误，必须显式转换

    反转：熟悉的外观（都是加法），陌生的严格

  ── 4.9 函数副作用必须标注 ────────────────────────────────

    hs 计算(a: u32) -> u32 { ... }        # 纯
    hs! 打印(s: *u8) -> k { ... }         # 有副作用（! 标记）

    调用纯函数与调用副作用函数在语法上可区分

    反转：把"副作用"从注释和文档提升为语言的一等公民
    【待决】内核代码大量有副作用，是否需要"模块级默认副作用"的豁免机制

  ── 4.10 并发由视图承担 ───────────────────────────────────

    共享状态 = 共享视图；同步 = 视图切换点

    【待决】具体原语设计未定。方向：不允许两个执行体同时持有一个可变视图

────────────────────────────────────────────────────────────────
五、命名与视图文法（BNF）
────────────────────────────────────────────────────────────────

  视图表达式   := 锚点 ( 跳转 )*
  锚点         := '@' | 标识符
  跳转         := '^' 展示标记? 名字
  展示标记     := '^^' | '^^^'          （写在 ^ 之后、名字之前）
  回退         := '~' ( 跳转 )*

  名字         := 标识符 | 字符串字面量        （含空格等特殊字符时用字面量）
  标识符       := 不允许包含：^ ~ @ . : * ! ? #
                  ★ 名字里禁止出现 ^，因此不需要转义规则（比 Unix 干净）

  求值语义：
    1. 从锚点开始，逐跳求值
    2. 每一跳失败 → 立即返回"名字不存在"，不回溯、不猜测
    3. 任何一跳都可能属于另一个地址空间/视图 → 权限与隔离天然生效
    4. 整个表达式的求值过程可被审计（记录每一次跳转）

────────────────────────────────────────────────────────────────
六、对象与存储格式
────────────────────────────────────────────────────────────────

  ── 6.1 对象 ────────────────────────────────────────────────

    ┌────────┬────────┬──────────┬────────────┐
    │ 类型标签│ 长度   │ 内容     │ 内容哈希   │
    └────────┴────────┴──────────┴────────────┘

    类型标签 := 内建类型码 | 结构体定义的对象哈希
    哈希     := 128 位或 256 位内容哈希【待决：BLAKE3 或 SHA-256】

  ── 6.2 存储后端：追加式日志 ───────────────────────────────

    ┌── 对象区（只追加，永不原地改）──────────────┐
    │ obj A (h1)                                  │
    │ obj B (h2)                                  │
    │ map_m (h3)   ← 映射对象（名字→引用）         │
    │ ...                                         │
    └─────────────────────────────────────────────┘
            ↑ 索引：哈希 → 偏移

  ── 6.3 映射对象 ────────────────────────────────────────────

    映射 = 排序键值对列表：名字 → 对象引用哈希 + 展示策略位
    映射本身是对象 → 由此得到：目录版本化、视图可回滚、历史永不丢失

  ── 6.4 视图 ────────────────────────────────────────────────

    视图 = 一组 (锚点名 → 映射引用哈希) + 能力集合

  ── 6.5 三种"修改"操作及其语义 ────────────────────────────

    绑定新名字      → 产生新映射对象，旧映射仍在（历史）
    解绑            → 同上
    复制对象        → 产生新内容对象 + 新映射

    结论：任何一次修改都不会破坏任何旧视图 —— 这是"天然回滚"的实现基础。

────────────────────────────────────────────────────────────────
七、语言与系统的一致性（这是别人抄不走的地方）
────────────────────────────────────────────────────────────────

  新语不是"另一门语言"，它必须与系统模型同构：

    系统公理              →  语言对应物
    ────────────────────────────────────────────────
    能力即引用（公理 5）  →  指针自带出处（4.7）
    无全局根（公理 3）    →  没有全局变量；一切访问从锚点开始
    不可变（公理 1）      →  bl 默认不可变；= 不是赋值（4.1）
    映射即对象（公理 6）  →  结构体/模块都是对象，可被版本化
    视图（公理 4）        →  函数的可见环境是显式传入的锚点集，不是全局符号表

  ★ 最后一条是核弹：**没有全局符号表**。函数要用什么，必须在签名里写出来。
    这在主流语言里几乎没有先例（最接近的是能力型语言与依赖注入）。
    它同时满足了"陌生""自洽""可验证"三个要求。

────────────────────────────────────────────────────────────────
八、可验证断言清单（CI 里的红灯与绿灯）
────────────────────────────────────────────────────────────────

  每一条断言都对应一条公理或一条语义反转。删掉对应设计，断言必挂。

  A1  [公理 1·不可变]   写入对象后校验哈希；日志只增不减；旧哈希内容不变
  A2  [4.1 绑定]        bl 之后赋值的程序 → 编译必须失败
  A3  [4.3 无权限不足]  用不存在的名字访问 → 错误必须是"名字不存在"，
                        且错误消息中不得出现"权限不足"字样
  A4  [4.4 展示策略]    默认列出时不出现 ^^ 名字；显式请求时出现
  A5  [公理 3·无根]     任何路径表达式的求值必须从锚点开始；
                        不存在能访问"全局一切"的表达式（用测试反向证明）
  A6  [公理 5·撤销]     撤销能力后，此前解析过的名字立即不可达
  A7  [4.7 指针出处]    跨地址空间使用指针 → 必须报错
  A8  [公理 7·原子]     视图切换过程中被中断（注入故障）→
                        要么完整切换，要么完全不变
  A9  [公理 6·映射]     同一内容两次写入 → 对象总数只增加一次（去重）
  A10 [4.1 默认不可变]  遍历全部测试程序：赋值语句数量 ≤ kb 声明数量

  ★ A10 是个有意思的元断言：它能从统计上证明"默认不可变"是真的落地的，
    而不是文档里写的口号。

九、"AI 懵逼测试"（本系统的验收标准之一）
────────────────────────────────────────────────────────────────

  目的：证明本系统具备"深层陌生性"，而不是"符号乱码"。

  方法：
    1. 取三段材料，不附任何解释：
         材料甲  .xy 源码片段
         材料乙  一条视图表达式（含 ^ 与 ^^）
         材料丙  一段真实错误消息
    2. 交给一个未接触过本系统的模型（人类专家同理），让它解释

  合格标准（必须满足两条）：
    ✅ 模型的初次推理链中，至少有一处被后续事实推翻
       （即：它的先验映射失效，产生"认知失调"）
    ✅ 模型在第二次回答时，无法再用任何现成系统作为类比

  不合格标准（任一出现即视为设计泄漏）：
    ❌ 模型直接正确归类为"某类 Unix"
    ❌ 模型说"这只是自定义符号的玩具语言"
    ❌ 模型能一次讲对 —— 说明我们的反转不够深

  【当前状态】规范 v0.1 尚未做此测试。待第 3 章里程碑跑通后执行。
