  新语 · 宿主版 —— 在 Linux 上直接写、直接编、直接跑
════════════════════════════════════════════════════════════════════

  一句话：**不用开 QEMU 了。** 写一个 .xy，编出来就是 Linux 的可执行文件，
          在终端里 ./它 就跑。

────────────────────────────────────────────────────────────────
  一、怎么用
────────────────────────────────────────────────────────────────

      sh 构建/建宿主.sh 你的程序.xy 输出名
      ./输出名

  例（仓库里带了一个示例）：
      sh 构建/建宿主.sh 示例/宿主你好.xy 你好
      ./你好

  生成的 10788 字节左右，**32 位静态 ELF** ——
  x86_64 的 Linux 直接能跑（内核的 IA32 兼容层默认开着），
  **不需要装任何 32 位库**（因为是静态的）。

────────────────────────────────────────────────────────────────
  二、原理（懂了就能自己扩展）
────────────────────────────────────────────────────────────────

  关键：**xyc 不变**。它对内核和宿主程序输出的是同一种 i386 汇编，
  区别只在【链接什么】：

      编内核：  你的.s + 运行时/图形.asm + 运行时/原语.asm
                → 内建函数接到【帧缓冲、端口、PS/2】上

      编宿主：  你的.s + 宿主/宿主.c
                → 内建函数接到【Linux 系统调用】上

  所以语言本身**一模一样**：数组、循环、结构体、递归、wx 危险块、
  指针、中文标识符 —— 全都是同一个编译器出的。

  宿主运行时在 宿主/宿主.c，一共 50 来个函数，
  把编译器要的符号一个一个实现对（清单在文件头上）。要加东西就往那儿加。

  ★★ 一个必须记住的约定：**参数顺序是反的**
      新语把参数【从左到右】压栈 → 第一个参数落在最深处
      而 C 的 cdecl 是第一个参数在 [esp+4]

      所以 宿主.c 里的 C 函数参数表要【倒着写】：
          新语  绘块(x, y, 宽, 高, 色)
          C     _gfx_fill(色, 高, 宽, y, x)

      返回值没问题（都在 eax），栈清理也没问题（都是调用方清理 add esp,N）。

────────────────────────────────────────────────────────────────
  三、能用的 / 不能用的
────────────────────────────────────────────────────────────────

  ▍完全能用（跟内核里一样）
      语言全部：hs fh bl kb qj jg rg bz dy xh tc jx wx
                数组、结构体、递归、指针、中文标识符
      wx 危险块 + 地址() + ^(址+k) 按字节读写内存   ← 真的能用
      读8 写8 读32 写32                             ← 真的能用
      调用(地址,a,b,c,d)                            ← 能用（函数指针）
      毫秒() 时() 分() 秒()

  ▍能用但行为不一样
      印串 / 印 / 出 / 印串(x)   → 打到终端 stdout
      清()                      → 发 ANSI 转义清屏（终端里有效）
      置光标(行,列)              → ANSI 转义
      键()                      → 读 stdin（**阻塞** —— 程序会等你按一下）
      屏宽/屏高                  → 假装是 80×25

  ▍不能用（在终端里本来也没意义）
      绘点 / 绘块 / 绘框 / 取点 / 绘块混 / 滚屏 / 滚块   → 空操作
      端入 / 端出 / 端入字 / 端出字                     → 返回 0
          （用户态没有端口权限，要 ioperm 才行）
      读CPUID / CPUE..CPUD                             → 返回 0
      绘字(x,y,串,色)                                   → 变成"打印串"（所以 屏串 能直接用）
      鼠x / 鼠y / 鼠钮 / 轮询                            → 0

  ▍所以
      模块/壳.xy 里那些 屏串 / 屏出 / 换行 / 屏数 / 打十六 这些【新语写的函数】，
      只要它们最后落到 绘字 / 绘块 上，宿主版就能直接用 ——
      因为它们本来就是新语代码，不是硬件操作。
      （这就是为什么"把桌面用新语写"这件事值钱：它能被搬走。）

────────────────────────────────────────────────────────────────
  四、踩过的两个坑（记下来省你时间）
────────────────────────────────────────────────────────────────

  ① 结尾的 cli / hlt
     编译器生成的 _start 结尾是：
         .Lhang:  cli / hlt / jmp .Lhang
     `cli` 和 `hlt` 是【特权指令】，用户态执行会 SIGSEGV。
     建宿主.sh 里用 python 把那三行替换成 `exit(0)` 的系统调用。
     （哪天编译器改了结尾样子，这一步会打印"⚠ 没找到 cli/hlt 结尾"）

  ② 别在 _gfx_init 里切 esp
     我第一版想在那里把 esp 换到一块自己的栈上，结果：
         _gfx_init:  mov $新栈,%esp   /   ret
     `ret` 会从【新栈】上弹返回地址 —— 那上面是 0 → 跳到 NULL → 段错误
     （qemu-i386 -strace 显示 si_addr=NULL，就是这么来的）
     正解：**什么都不用做**。_start 那句 `mov esp, offset _kernel_stack_top`
     已经把栈设好了 —— 只要在 _kernel_stack_top 前面放一个大数组
     （宿主.c 里的 栈区[256KB]），链接器会把它排在数组末尾，正好是栈顶。

────────────────────────────────────────────────────────────────
  五、调试工具
────────────────────────────────────────────────────────────────

      qemu-i386 -strace ./你的程序      看每一个系统调用
      qemu-i386 ./你的程序              跑（aarch64 机器上要这样跑）
      ./你的程序                        x86_64 上直接跑

      i586-alpine-linux-musl-objdump -d 你的程序 | head -30    看反汇编

  ★ 在你自己的 Arch 上，直接 ./ 就行，不用 qemu-i386。

────────────────────────────────────────────────────────────────
  六、为什么这件事重要
────────────────────────────────────────────────────────────────

  1. **学语言变快十倍** —— 改一行 → 编 → 跑，两秒钟看到结果。
     在内核里改一行要构建 ISO + 起 QEMU + 点鼠标，几十秒。
  2. **能写小工具** —— 你现在可以真的用新语写个"能干活的程序"：
     算文件哈希、转格式、批量改名…… 它就是个正常的 Linux 程序。
     ★ 而且这些东西以后可以【原样搬回混沌】——
       因为语言是同一个，只是链接的对象不同。
  3. **证明了一件事**：内核里的业务代码（视图、盘格式、包格式……）
     高度不依赖硬件。真正绑在硬件上的只有那 50 来个内建函数。
     → **这就是"内核该分家、每个器官一个包"那条路的第一块砖。**
