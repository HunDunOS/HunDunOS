        单调轴：令牌轮换与撤销的统一   v0.1
        来源：作者提出"内核每次发一个新哈希，旧的消失"
        作用：合并两个待决项，并为"权柄不可回退"提供实现
════════════════════════════════════════════════════════════════

────────────────────────────────────────────────────────────────
零、作者的原话与本文任务
────────────────────────────────────────────────────────────────

  作者原话（整理）：
    "新语里不是每个东西都有哈希值吗？能不能让内核每次发一个新的，
     旧的会消失。攻击者拿到的是旧的，用不了。"

  任务：
    1. 给它正名并形式化（安全工程里这叫令牌轮换 token rotation）
    2. 检查它与已有机制的关系
    3. 明确它能解决什么、不能解决什么

  结论先行：
    ★ 这个想法**合并了两个待决项**，并让"权柄不可回退"这条公理
      第一次有了具体实现。
    ★ 它还顺手给"内核最大风险（本源缺陷）"指出了解决路径。

────────────────────────────────────────────────────────────────
一、它能解决什么（比我原来的方案更完整）
────────────────────────────────────────────────────────────────

  原本有两个待决项在互相拉扯：

    I2  线性能力（用完即失效）与"需要长期持有的服务"冲突
        → 不能每用一次服务就重新申请一次能力

    A37 能力随数据泄漏
        → 原方案"封印（密文）"只能防"复制出去用"，
          防不住"合法持有者本人泄漏"

  令牌轮换同时解决两者：

    · 不是"用完即废"，而是"**用完即换新**"
      → 长期持有不再是问题（服务能力可以反复使用）

    · 旧令牌即使泄漏，**下一次合法使用一发生，它就死了**
      → 泄漏的窗口被压缩到"两次使用之间"

────────────────────────────────────────────────────────────────
二、关键发现：轮换与撤销是同一个机制
────────────────────────────────────────────────────────────────

  原本设计了两套机制：

    撤销  →  墓碑集合（已撤销能力的集合，单调）
    轮换  →  世代号（每次使用 +1）

  观察：**这两个是同一个机制的两个操作。**

    操作    单调轴上的动作
    ────────────────────────────────────────────────
    轮换    世代号 +1，**仍签发新的**
    撤销    世代号推进到墓碑，**不再签发新的**

  于是不需要两套机制，只需要一条：

  ┌────────────────────────────────────────────────────────────┐
  │  单调轴（monotonic axis）                                   │
  │  内核里唯一只增不减的东西。不属于任何态。                    │
  └────────────────────────────────────────────────────────────┘

  ★ 由此，"权柄不可回退"这条公理（前文安全模型 §4）第一次有了实现：

      · 态：在轴上可自由回退（历史永远可得）
      · 轴：不属于任何态，只增不减
      · 投影规则：任何时间坐标的投影 = 先过轴，再过态（顺序不可交换）

────────────────────────────────────────────────────────────────
三、形式化
────────────────────────────────────────────────────────────────

  ── 3.1 能力对象 ────────────────────────────────────────────

      能力 = ( 对象哈希, 授权描述, 世代号, 签名 )

  ── 3.2 校验规则 ────────────────────────────────────────────

      使用能力时：
        世代号 == 内核当前记录的"该能力世代号"   → 有效
        否则                                     → 失败

  ── 3.3 使用与轮换 ──────────────────────────────────────────

      一次成功使用 → 推进该能力的世代号
                   → 把新世代**通过本次调用的返回通道**交还持有者

    ★ 关键细节：新世代必须从"这次调用"的返回通道交还。
      不能让持有者自己去"取新的" —— 否则泄漏者也能去取。

  ── 3.4 内核状态的极简化 ────────────────────────────────────

      除单调轴之外，内核里的东西全是不可变的
      （态、迹、视都是对象）。

      → **内核里唯一的可变状态，就是这条只增不减的轴。**

────────────────────────────────────────────────────────────────
四、它做不到什么（诚实边界）
────────────────────────────────────────────────────────────────

  ── 4.1 竞态：先到先得 ─────────────────────────────────────

    如果攻击者在合法持有者**之前**使用泄漏的令牌，他能赢。

    但是：合法持有者下一次使用会立刻失败
      → 从"静默窃取"变成"**可检测窃取**"
      → 这是实打实的进步，但不能说"防住了"

  ── 4.2 未使用时不移除 ─────────────────────────────────────

    合法持有者长期不使用 → 泄漏的副本一直有效。

    缓解：
      · 配合封印（密文）：副本本身就用不了
      · 时间锚定过期：超过某个时间坐标自动推进世代

  ── 4.3 内核缺陷仍在 ───────────────────────────────────────

    本源被攻破 → 一切归零。见第五节。

────────────────────────────────────────────────────────────────
五、必须加的约束：轮换只能用于"独占"能力
────────────────────────────────────────────────────────────────

  ── 5.1 问题 ───────────────────────────────────────────────

    两个分身共用一个能力：
      分身 A 用了一次 → 世代 +1 → 分身 B 的令牌立刻失效
      → 变成互相踢人

  ── 5.2 规则 ───────────────────────────────────────────────

    轮换只适用于**独占**能力。
    共享必须**派生独立血统**（各轮换各的）。

    ★ 这条正好用上已有机制：衰减派生。
      共享 = 从原能力派生两份，各自独立轮换。
      → 两个设计天然咬合，不需要新机制。

  ── 5.3 判定方式 ───────────────────────────────────────────

    能力创建时必须显式声明：独占 or 共享。

      · 独占：可轮换（默认）
      · 共享：禁止直接轮换；必须先派生

    违反 → 报错（见断言 A45）

────────────────────────────────────────────────────────────────
六、附加收益：它给出了"内核最大风险"的解决路径
────────────────────────────────────────────────────────────────

  前文安全模型列出的最严重残余风险：

    R3  本源（内核）自身缺陷 → 一次 bug = 全盘失守
        无法用设计消除，只能靠"内核最小化 + 形式化验证"

  本设计推进了这一步：

    · 内核里唯一的可变状态 = 一条只增不减的轴
    · 其余全不可变（态、迹、视都是对象）

  推论：
    · 内核接近**无状态** → 状态空间极小 → 形式化验证难度断崖式下降
    · 攻击者能操纵的"可变面"只剩一条单调计数器

  ★ 也就是说：**"内核够小"这件事，从"体积问题"变成了
    "可变状态数量问题"** —— 这才是可验证的定义。

────────────────────────────────────────────────────────────────
七、新增可验证断言（接 A1–A41）
────────────────────────────────────────────────────────────────

  A42 [轮换生效]     使用一次能力后，其旧世代副本必须失效

  A43 [窃取可检测]   攻击者用旧世代令牌 → 失败；
                     且合法持有者下一次使用能感知到自己被顶掉

  A44 [轴不可回退]   回到任何历史态，世代号不得回退（与 A38 呼应）

  A45 [独占/共享]    两个分身未派生血统而共享同一能力，轮换时必须报错

  A46 [内核可变面]   枚举内核二进制中的可变状态：只能有一条单调轴
                     （反向断言：出现第二处可变全局状态即失败）

  ★ A46 是本项目的又一条元断言：
    它把"内核够小"从形容词变成了可跑的检查。

────────────────────────────────────────────────────────────────
九、【重要修订】与 Steam / TOTP 的对照：轮换有两种模型
────────────────────────────────────────────────────────────────

  作者提出类比："就像 Steam 令牌一样"。

  这个类比让我发现 §3.3 的设计需要修订，故单列一节。

  ── 9.1 两种轮换，本质不同 ──────────────────────────────────

    维度           无状态轮换（Steam Guard / TOTP）   有状态棘轮（本文原方案）
    ──────────────────────────────────────────────────────────────────────
    原理           密钥 + 当前时间窗 → 双方各算一个码   内核记录世代号，用一个 +1
    需要存状态吗   **不需要**                            需要（每个能力记一个世代）
    泄漏后果       **致命**：拿到密钥可算未来所有窗口     旧副本在下次合法使用后自动死
    适用场景       证明"你持有那个设备"                  授权"你这次能用"

    ★ 事实上 Steam 两种都用：
        · Steam Guard（手机验证器）= TOTP 式，无状态，30 秒一轮
        · 会话令牌 = 有状态、可服务端撤销
      两者解决的问题不同，缺一不可。

  ── 9.2 由此修订 §3.3：把"每次使用都推进轴"改为无状态轮换 ──

    原设计：每次使用 → 推进世代号（写轴）
    问题：  **轴会随使用次数无限膨胀**（即待决项 J1）

    修订后：

        轮换：密钥 + 时间窗口 → 双方各自计算，内核不存任何东西
        撤销：显式加入墓碑集合 → 只有撤销才写轴

    结果：
      · 轴的增长只由"撤销"驱动，不再由"使用次数"驱动
      · J1（轴膨胀）与性能问题一并缓解
      · 内核的可变面进一步缩小

  ── 9.3 为什么这条路在本系统里是"免费的"──────────────────

    其他系统要用无状态轮换，必须先引入一个时钟。

    **本系统里"时间坐标"本来就是一等公民（时态内核 §2.3）**，
    因此 TOTP 式轮换不需要任何新机制 —— 直接复用"视的时间坐标"。

    ★ 这是"世界观先行"带来的红利：别的系统要额外搭的东西，本系统天生就有。

  ── 9.4 致命边界：无状态轮换不能单独使用 ───────────────────

    TOTP 式的轮换，**共享密钥一旦泄漏 = 未来所有窗口都能算**。

    也就是说：若只用无状态轮换，能力泄漏问题**从"旧副本失效"
    恶化成"未来全废"**。

    因此最终形态必须是四层叠加：

      问题                          用什么机制
      ──────────────────────────────────────────────────────────
      泄漏的副本能不能用            封印能力（绑定持有者密钥，副本解不开）
      能不能重放                    无状态轮换（时间窗口，过期即废）
      用完能不能继续用              独占能力 + 派生血统
      能不能回到过去绕过撤销        单调墓碑（权柄不可回退）

    ★ 四层各管一件事，缺一层就漏。
      这也是为什么"轮换"不能取代"撤销" —— 它们防的不是同一类攻击。

────────────────────────────────────────────────────────────────
十、新增断言（接 A1–A46）
────────────────────────────────────────────────────────────────

  A47 [无状态轮换]   不写轴的情况下，过期时间窗口的令牌必须失效
  A48 [密钥泄漏边界] 泄漏共享密钥（未封印）必须导致失败，
                     而不是静默通过 —— 即系统必须拒绝"无封印能力"
  A49 [轴增长只由撤销驱动]
                     执行 10^6 次能力使用后，轴的长度必须**不变**；
                     执行 1 次撤销后，轴长度 +1
  A50 [时间坐标复用] 无状态轮换所依赖的时间坐标，
                     必须与"视的时间坐标"是同一个来源（不得引入第二个时钟）

  ★ A49 是这条修订的核心验收：它把"轴不随使用增长"变成可跑的检查。
