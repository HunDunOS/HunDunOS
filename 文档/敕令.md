## 提示符

```
敕 hundun 令      大道，view == 0
勅 work   令      天道，view > 0
```

提示符里的字由 `当前view` 查出来，不是配置出来的。

## 权柄分级

```
大道  view == 0    全部 27 条
天道  view > 0     按签发时给的能力位，逐条过 view_要能力
```

敲下一条命令，先过能力位，再执行。**没这能力位，命令当场拒，不是执行失败。**

## 不跨系统

**敕令是混沌内核的东西，哪也不去。**

跨系统的是五行这门语言本身；敕令不是。它调的全是混沌独有的概念：

```
db 道标    只有混沌有 .dao
gd 轨道    只有混沌分阴阳两轨
sd 世代    只有混沌的道标里记世代
cl 敕令    只有混沌有大道与天道
cc 存储    只有混沌有 HDGX 内容寻址对象区
sb 设备    只有混沌有能力表
```

把这些搬到 Linux 上，`db` 得打印什么？没有道标。`cl` 得报什么？没有天道。

**五行只是写它的笔，不是它的绑带。** 笔可以换地方写别的字，字本身离不开这块地。

所以：

| 东西 | 跨不跨 |
|---|---|
| 五行语言（wx / .wx） | ✅ 跨系统，宿主各实现一份 |
| 敕令（26 条命令） | ❌ 只属于 Hundun |

## 夺舍（ds）

**切换和夺舍的区别，就在"目标正在跑的时候"。**

```
qh 1   切换  温柔交班：目标睡着就唤醒它，大道干到一半的活存回去
ds 1   夺舍  强夺：不管目标在不在跑，冻结它的上下文，直接接管躯壳
ds     无参  夺回大道（大道永远在，不存不载）
```

**夺舍三步**（视图层已有）：

```
① 存回   把当前视图的名字表 / 映射池写回 view池
② 载入   把目标视图的名字表 / 映射池读出来
③ 改主   当前view = 目标号
```

**被夺舍的天道会怎样**：它的寄存器、栈原样冻结在内存里，但它不再是 `当前view`，
**从此它说的话不算数**。想回去就 `ds 0`。

**为什么大道能夺舍别人，别人夺不了大道**：`view 0` 不存不载，它一直都在。
这就是 `view_签发` 只允许 `当前view == 0` 的原因 —— **只有没被夺舍过的大道才能签发新天道。**
