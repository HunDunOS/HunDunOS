        对照 OSI 那套讲法：自下而上七层
                                    2026-10-03

  为什么要定这个
  ──────────────
  OSI 把网络拆成七层，好处是每层只关心自己、不关心下层怎么实现。
  混沌也需要一套同样的讲法 —— 否则跟人解释"它跟 Linux 差在哪"，
  最后都会落到"差在实现细节"，那是讲不清的。

  真正差在【层】上：Unix 有三层是很重的大机器，而这三层在混沌里退化了。

────────────────────────────────────────────────────────────────
  逐层对照：每一层在 Unix 里对应什么，混沌换成了什么
────────────────────────────────────────────────────────────────

  ── 层 7  视图 ───────────────────────────────────────────────
     Unix 对应：进程的地址空间 + 文件描述符表
     混沌换成：一组锚点 + 一个映射引用（几十字节）
     ★ 差别：**混沌没有"地址空间"这个概念。**
       Unix 的"同时" = 多个地址空间轮流上 CPU；
       混沌的"同时" = 多个视角轮流指向同一份对象。

  ── 层 6  分身 ───────────────────────────────────────────────
     Unix 对应：用户 / 账户 / 组 / 登录 / 提权
     混沌换成：视图 + 能力集 + 父引用；**唯一能签发能力的是「本源」（内核本身）**
     ★ 差别：**没有 root，也没有"用户"这个概念。**
       它消掉的不是一个词，是一整层概念（账户/组/登录/提权/管理员身份）。

  ── 层 5  能力 ───────────────────────────────────────────────
     Unix 对应：系统调用（open / read / write / close / link / unlink …）
     混沌换成：七条原语
               存     内容 → 引用（算哈希、查重、没有才追加）
               取     引用 → 内容（引用不对就取不出来）
               列     当前视图里可见的映射项
               映射   名 → 引用，产生新映射对象
               视图   原子切换视图根
               撤销   轴上追加墓碑
               跨越   从锚点出发的一跳（就是 ^ 这个符号）
     ★ 差别：**路径字符串不是通行证。**
       Unix 上 open("/etc/shadow") 能不能开，取决于你是谁；
       混沌上你得【先有】那个引用，不存在"路径字符串绕过引用"这条路。

  ── 层 4  对象 ───────────────────────────────────────────────
     Unix 对应：inode + 文件（可变、就地修改、日志保护一致性）
     混沌换成：内容哈希 + 不可变对象（只追加）
     ★ 差别：**名字就是内容。**
       内容一变名字就变 → 静默损坏不可能、去重白送、版本历史白送、
       撤销白送（换回旧引用，原子，不需要 undo 日志）

  ── 层 3  混沌盘 ─────────────────────────────────────────────
     Unix 对应：文件系统（ext4 / Btrfs：目录树 + 日志 + 快照）
     混沌换成：图（对象 DAG）+ 超级块 + 索引区 + 单调轴
     ★ 差别：**没有目录树，所以也没有"挂载"。**
       树必须有一个根，而公理 3 说【没有全局根】。
       所以盘格式不可能是树，只能是图。

  ── 层 2  块设备 ─────────────────────────────────────────────
     Unix 对应：块层 + IO 调度器（电梯算法 / CFQ / deadline …）
     混沌换成：ATA PIO，够用就行
     ★ 差别：**只追加 → 不需要 IO 调度。**
       写永远往末尾去，天然顺序；Unix 需要调度器是因为它会随机写。

  ── 层 1  硬件 ───────────────────────────────────────────────
     这一层大家都一样：CPU / 内存 / 端口 / 帧缓冲。
     只提一句：混沌到现在**没有开中断**（没有 IDT，没有调度器），
     一切靠轮询 —— 这是有意的，见《回答-混沌的调度器怎么实现的.txt》。


────────────────────────────────────────────────────────────────
  ★ 最该记住的一段：Unix 的三台大机器，在这里全部退化
────────────────────────────────────────────────────────────────

  ┌──────────────────────┬────────────────────────┬──────────────────────┐
  │ Unix 里的大机器        │ 它为什么复杂            │ 混沌里它变成什么      │
  ├──────────────────────┼────────────────────────┼──────────────────────┤
  │ 虚拟内存              │ 每个进程一个地址空间     │ **不存在**           │
  │ (MMU / 页表 / TLB)    │ 换进程要刷 TLB          │ 只有"视图"           │
  ├──────────────────────┼────────────────────────┼──────────────────────┤
  │ 文件系统              │ 就地修改要保证一致性     │ **只追加**           │
  │ (ext4 / Btrfs + 日志) │ 所以要日志 / COW / 快照  │ 一致性免费           │
  ├──────────────────────┼────────────────────────┼──────────────────────┤
  │ 权限                  │ 身份与权限分离           │ **能力即引用**       │
  │ (root / user / ACL)   │ 所以要一整套身份体系     │ 没有身份这个概念      │
  ├──────────────────────┼────────────────────────┼──────────────────────┤
  │ IO 调度               │ 随机写要重排             │ **只追加**           │
  │ (电梯 / CFQ)          │ 所以要预测和排序         │ 天然顺序             │
  └──────────────────────┴────────────────────────┴──────────────────────┘

  这四台机器加起来，就是常规操作系统里绝大部分复杂性所在。
  混沌不是"用更好的办法实现了它们"，而是**让它们没有存在的必要**。


────────────────────────────────────────────────────────────────
  一句话对照（三种世界的分层）
────────────────────────────────────────────────────────────────

        OSI            Unix                 混沌
        ─────          ──────               ──────
        7 应用          应用                 视图
        6 表示          库                   分身
        5 会话          系统调用              能力
        4 传输          进程 / 文件           对象
        3 网络         虚拟内存              混沌盘
        2 链路          设备驱动              块设备
        1 物理          硬件                 硬件

  符号上也对得上：

        Windows   \    路径是树的地址（向下）
        Unix      /    路径从根出发（向下）
        混沌      ^    路径是一次能力跨越（向上）—— 因为【没有根】

  附：现在做到哪一层了（2026-10-03）
────────────────────────────────────────────────────────────────

  层 1  硬件        ✅  自研引导器 + XBP 协议
  层 2  块设备      ✅  ATA PIO（用新语写的，无一行 C）

  层 5  能力        🔧  存/取/列/映射/撤销 五条都通了；
                       "视图""跨越"还没做实（^ 现在还是指针解引用）
  层 6  分身        ❌  只有设计文档（分身模型 v0.1）
  层 7  视图        ❌  盘上留了位置（LBA 2），没做实
