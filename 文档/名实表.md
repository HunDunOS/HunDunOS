# 名实表 —— 每个字对应哪一套物理

> 规矩：**一个字必须同时满足三项，才配留在代码里。**
>
> ```
> ① 有出典    古书里有这个用法，不是我编的
> ② 有物理    对应一条真实机制（内存、总线、时序、状态机），不是比喻
> ③ 有代码    仓库里有这个文件、这个函数，能指出行号
> ④ 有实况    跑没跑过、过没过、卡在哪 —— 不许写「已完成」
> ```
>
> **缺第 ② 项就是中二，缺第 ④ 项就是骗人。** 这张表两个都不许缺。

## 一、道生一，一生二，二生三，三生万物

出典：《道德经》四十二章、《易·系辞》「易有太极，是生两仪」

| 字 | 出典 | 物理机制 | 代码 | 实况 |
|---|---|---|---|---|
| **道** | 「一阴一阳之谓道」 | 机器交付时唯一的入口地址，此后一切从这里分出去 | `Dao.efi`（PE32+，UEFI 固件直接加载），入口 `efi_main` | ✅ 通。串口打出 `HunDunOS - XBP boot` |
| **一** | 「抱一以为天下式」 | 长模式下的单一平坦地址空间，无分段 | `efi桩.asm` 出生即 64 位 | ✅ 通。`[ ok ] GOP fb=0x80000000` |
| **二** | 「是生两仪」 | 同一份装载格式，两个落址、两个卦象 | `yu0.dao` 卦 0 落址 `0x100000`；`yu1.dao` 卦 63 落址 `0x300000` | ✅ 通。两份 FNV 指纹都打在串口上 |
| **三** | 「二生三」 | 阴阳两轨**相合**，生成第三个可执行体 | `hundun.dao` 卦 **21** 落址 `0x180000` | ✅ 通。`J000000000018` 打出来后跳进 `X` |
| **万物** | 「三生万物」 | 每个模块一个卦象、一个落址，装轨时按卦校验 | `模块/成品/*.dao` 七个 | ⚠️ 七个全部装载成功（指纹齐打），**只有一个真被调用过** |

**「三」不是虚数**：卦 21 = 六爻上下皆「阴阳交错」，不是全阴（0）也不是全阳（63）。**这个数字是算出来的，不是取的名字。**

## 二、界面四字：页、布、简、编

出典：《说文》「简，牒也」「页，头也」（引申为书页）、「布，枲织也」（引申为铺陈）、「编，次简也」

| 字 | 出典 | 物理机制 | 代码 | 实况 |
|---|---|---|---|---|
| **页** | 书页：一页就是一整版的静态内容 | **离屏缓冲**：先在一整块内存里排好，再整体翻出来 | `页.ly` 节点表 `0x30000`，每节点 8 个 u64 | ⚠️ 编译过（11 函数），**从没被调用** |
| **布** | 「布，铺陈也」：经纬排开 | **布局引擎**：抽象节点 → 具体矩形 → 文字位置 | `布.ly` 节点表 → 矩形表 `0x34000` → 文字表 `0x38000` | ⚠️ 编译过（8 函数），**从没被调用** |
| **简** | 「简，牒也」：竹片一根一根排成行 | **字符帧缓冲**：一格一个字符 + 前景 + 背景，按行排 | `简.ly` 40×25 网格 `0x20000`，每格 4 字节（字 \| 前景<<8 \| 背景<<16） | ⚠️ 编译过（17 函数），**从没被调用** |
| **编** | 「编，次简也」：把竹简编排成册 | **编辑器缓冲**：改内容、标记脏行、光标定位 | `编.ly` 缓冲 `0x50000`，64 行 × 80 列 | ⚠️ 编译过（11 函数），**从没被调用** |

**这四个字是同一件事的四层**：
```
页 = 内容（要显示什么）
布 = 排布（放在哪、多大）
简 = 显字（一格一格画出来）
编 = 改动（人在这里改内容）
```
**顺序不能乱：页 → 布 → 简 → 编，正好是「读→排→画→改」。**

## 三、象

出典：《易·系辞》「**象也者，像也**」「圣人立象以尽意，设卦以尽情伪」

| 字 | 出典 | 物理机制 | 代码 | 实况 |
|---|---|---|---|---|
| **象** | 象 = 像：把看不见的「意」显成看得见的「形」 | **离屏合成**：在一块独立的「面」内存里画，再整块搬到帧缓冲 | `象.ly` 面基 `0xC00000`，640×400×4 | 🔄 **半通**：`象_面`、`象_块` 已通（标记 `ab` 打出）；`象_圆` 卡在 `q6 = gr hz q1` 那行，`象_合` 尚未验证 |

## 四、时空三字：浑天、历、爻

出典：《晋书·天文志》张衡浑天说、《大明历》祖冲之、爻为卦画

| 字 | 出典 | 物理机制 | 代码 | 实况 |
|---|---|---|---|---|
| **浑天** | 浑天仪：用一件仪器同时定时间与方位 | **因果寻址**：因果 → 十二地支（时间维）→ 二十八星宿（空间维）→ LBA | `因时空.ly` 公式 `LBA = 基 + (时*28 + 宿)*跨` | ❌ 编译过（10 函数），装轨了，**从没被调用** |
| **十二地支** | 子丑寅卯辰巳午未申酉戌亥 | 盘的**时间维**，12 段 | 同文件，`时 = 因果 & 0xFF` | ❌ 同上 |
| **二十八星宿** | 角亢氐房心尾箕…（东方苍龙七宿起） | 盘的**空间维**，28 段 | 同文件，`宿 = (因果>>8) & 0xFF` | ❌ 同上 |
| **历** | 祖冲之《大明历》：回归年 365.2428 日 | **进位链**：秒→分→时→日→月→年，逐级进位 | `历.ly` 从 2026-11-06 起算 | ⚠️ 编译过（6 函数），**没上机** |
| **爻** | 卦的每一画，六爻成一卦 | **位**：一个 u64 的每一位当一画，位运算 = 爻变 | 全语言：`hs hr hd dh dl dr` 六条位运算卦令 | ✅ 通。定点运算全靠它 |

**12 × 28 = 336 不是随便挑的两个数**：地支是时间的最小周期，星宿是天空的固定分区，**浑天仪的刻度盘就是这个数**。

## 七、数：为什么只留两个常数

出典：祖冲之《缀术》密率 355/113

| 项 | 物理机制 | 实况 |
|---|---|---|
| `定一 65536` | Q16.16 定点，低 16 位是小数 | ✅ 3 处调用 |
| `定PI 205887` | 355/113 × 65536 = 205887（误差 0） | ⚠️ 只有测试打印过，**画圆弧才需要它** |
| `sq` 牛顿开方 | `x'=(x+n/x)/2` 整数迭代 | ✅ 串口实测 `sqrt144= 12`、`14400→120` |
| `fb` 斐波那契 | 分配块大小用 | ✅ 修好后实测 `fib20= 6765` |
| `mc` / `dc` 定点乘除 | 移位 + 整数除 | ✅ 数测 PASS |

**删掉的五个常数（`定E` `定根2` `定ln2` `定PHI` `定PHI倒`）**：值是真的，算式也好，但**零调用**。
按规矩「有调用者才算」，删。值记在本文末尾，将来要用再加一行。

## 九、盘上五行（2026-11-07 定，五个块各管一件事）

**取代原来的「A/B 双超级块」。** 双块只解决「写到一半掉电读到哪个」，五行解决「坏了能不能重建」。

| 五行 | 性 | 管的区 | 为什么是它 | 相生（生） | 相克（死） |
|---|---|---|---|---|---|
| **水** | 藏、源头 | **超级块根**（LBA 0） | 藏最深，读它就够 | 金生水：边界满了 → 根下一代 | 土克水：轴到头 → 根不能再长 |
| **金** | 决断、肃杀 | **边界与代数**（LBA 1） | 哪个对象活、哪代作废，一刀判 | 土生金：轴走到哪，边界跟到哪 | 火克金：视图收回 → 边界回退 |
| **火** | 炎上、显明 | **视图记录区**（LBA 2） | 火照亮：谁在看着、谁能动 | 木生火：索引找得到对象，才知视图记得谁 | 水克火：根换代 → 旧视图全作废 |
| **木** | 生发、伸展 | **索引区**（LBA 3） | 索引跟着对象长出来 | 水生木：根知道索引在哪 | 金克木：边界判这代作废 → 索引整块失效 |
| **土** | 承载、居中 | **轴区**（LBA 4 起） | 土承全盘；轴只增不减 | 火生土：视图发一次，轴记一笔 | 木克土：索引说没了 → 轴到此为止 |

```
LBA 0     水  超级块根
LBA 1     金  边界与代数
LBA 2     火  视图记录
LBA 3     木  索引
LBA 4     土  轴（起）
LBA 5..   对象区（只追加）
LBA 4096.. 轴区续
```

**相生和相克不是两个方向，是两个动作：**
```
相生 = 从上游要一份   （某块坏了，沿着相生链往上游重建）
相克 = 一刀切断       （某块作废，沿着相克链往下游终止）
```

`五行调度.ly` 里的 `生 = +1%5`、`克 = +2%5` 就是这两条链的序号运算 —— **调度用的和盘用的是同一条链，不是两套。**

### 实况（必须写清）

```
✅ 设计已定          本节
❌ 五个块没有落盘    因时空.ly 写超级块是写内存缓冲，不是写盘
❌ 相生重建路径       一行代码都没有
❌ 相克作废路径       一行代码都没有
❌ 多核并发           全系统单核跑，MP Services 只是拉起来，没有并发写盘
```

**所以现在谁也不能说「五块互相校验」，只能说「五块的分工已定，实现待做」。**

## 十、页表（2026-11-07 记一个硬事实）

`yu0` 那句话是「**页表由固件已建**」—— 全项目**零行**页表代码。

```
固件的页表只映射它自己需要的内存
0xC00000（象的面）   大概率没映射 → 往里写 = 缺页
0x80000000（帧缓冲） 映射了，但可能只读
ExitBootServices 之后，没有异常处理程序接住缺页
                  → 一旦触发，#PF 无处可去，CPU 卡死
```

**这是「圆画不出来」最可能的真正原因，比算法 bug 更根本。**
修法：`yu0` 里自己建一张页表，把 0~4GB 全映射成可写（2MB 大页，两个 PDPT 就够）。

**实况：❌ 未做。**

## 十一、名字怎么取（2026-11-08 定，不再反复）

```
文件     直白，一眼看出干什么        大道 / 墨 / 工 / 简 / 象 / 布 / 页 / 编
层次     可以借用典故讲             道层玉清 / 象层上清 / 器层太清
```

**文件不借典故的原因：**

```
玉清门.asm  →  没人猜得到是 UEFI 引导
工.asm      →  谁都知道是最小工具
```

**层次借典故的好处：**

```
「混沌分三清：道层玉清、象层上清、器层太清」
   一句话说清系统分几层，比「应用层/内核层/引导层」有味道
   而且和易（六爻）、天文（浑天）是同一套话语
```

**两条一分开，就都成立了：文件负责能被读懂，典故负责讲清结构。**

## 十二、这张表的用法

**任何人问「你这不是中二吗」，把这张表推过去。**

```
「简」不是编个古风名字 —— 简.ly 里是 40×25 的字符帧缓冲，每格 4 字节，17 个函数

「二生三」不是排比 —— 卦 21 的 hundun.dao 已经在 0x180000 跑起来了
```

**反过来，谁要问「你做到了吗」，这张表第四列就是答案。**
