# 底层实录 —— 混沌是怎么从固件手里接过机器的

> 这份文档只记录**踩出来的事实**，不写想象。每条都有寄存器、日志或反汇编作为证据。

---

## 一、为什么用 UEFI 而不是 BIOS

BIOS 引导的路：

```
实模式 16 位 → A20 → 保护模式 32 位 → 分页 → 长模式 64 位
      ↑ 每一步都要手写，每一步都可能三重故障
      ↑ 还要自己写 INT 13h 读盘、自己找 VBE 模式
```

UEFI 的路：

```
一进门就是 64 位长模式 + 恒等映射页表 + 图形协议 + 块设备协议
```

**所以混沌的引导器没有一行 32 位代码。** A20、GDT、保护模式、VBE 全部消失 —— 那些东西固件已经做完了。

代价只有一个：**必须叫 `\EFI\BOOT\BOOTX64.EFI`**，这是固件的死规矩，绕不开。但也就这一个妥协。

## 二、XBP 道标：为什么是八个 u64

传统加载器要外部元数据：ELF 的程序头、链接脚本里的地址、加载器的约定。

XBP 把这些全塞进文件自己的头里，**八个 u64，一个 32 位字段都没有**：

| 偏移 | 名 | 作用 |
|---|---|---|
| +0 | 道标 | `"HUNDUNV1"` |
| +8 | 卦象 | 0 = 全阴（阴轨），63 = 全阳（阳轨） |
| +16 | 落址 | 加载到哪 |
| +24 | 长度 | 机器码多少字节 |
| +32 | 指纹 | FNV-1a 64 |
| +40 | 入口 | 相对机器码起点的偏移 |
| +48 | 世代 | 第几版 |
| +56 | 头印 | 前 56 字节的 FNV，头自己校验自己 |

**四道闸，缺一不放行：**

```
道标 HUNDUNV1 → 头印自校验 → 卦象匹配 → 机器码指纹
```

任一不过 → 打印 `SEAL/HASH MISMATCH - refused` → 停机，**绝不执行一个未知字节**。

**关键一条**：入口 = `落址 + 64 + 入口偏移`。道标占前 64 字节，这个 `+64` 忘了会跳到道标上执行 `"HUNDUNV1"` —— 实测就是这么崩的（`#UD @ 0x300025`）。

## 三、页表只到 2MB（血的教训）

实测结论：

| 段落址 | 结果 |
|---|---|
| **0x100000**（1MB，阴） | ✅ 正常执行 |
| **0x200000**（2MB，阳） | ✅ 边界可用 |
| **0x300000**（3MB，合） | ❌ **`#PF`** |

```
RIP = 0x300038   CS = 0x38
Exception 0E (#PF - Page-Fault)
```

**OVMF 的页表没有映射到 3MB。** 这不是 bug，是固件按需映射的结果。

**所以规矩定死**：引导阶段所有段落址必须 **< 0x200000**。要跑在更高地址，必须自己建页表（那是内核的活，不是引导器的）。

这条直接决定了合轨从 `0x300000` 挪到 `0x180000` 之后，异常从 `#PF` 变成 `#UD` —— **能取指了，只是指令有问题**，问题层级完全不同。

## 四、多核：固件已经把 AP 拉起来了

单核跑引导是浪费。i5-9300H 有 8 个逻辑核，9950X3D 有 32 个。

**UEFI 有 MP Services 协议**，直接能用：

```
GUID: 3FDDA605-A76E-4F46-AD29-12F4531B3D08

GetNumberOfProcessors(This, &总数, &已启用数)     → 实测 cores 8, enabled 8
StartupAllAPs(This, WaitEvent, Timeout, 过程, 参数, Single)  → AP 全部上阵
```

**不用写一行 `INIT-SIPI-SIPI`** —— 那是 ExitBootServices 之后才需要的东西（那时固件已经没了）。

### 但有个毒坑

**AP 过程里不许有任何 UEFI 调用**，连打印都不行。因为：

```
BSP 执行 ExitBootServices → ConOut / GOP / BlockIo 全部失效
                                 ↓
AP 若此时正在 SystemTable->ConOut->OutputString 里 → #GP 当场死
```

**还有两个更阴的**：

1. **AP 的栈是固件分配的**（`EfiBootServicesData` 类型），Exit 之后会被内核当空闲区覆盖 → 栈被踩，直接暴毙
2. **AP 的代码段如果落在会被回收的区域** → 同样完蛋

**正确姿势**：

```
1. 自己 AllocatePages 拿 AP 栈（EfiLoaderData，Exit 后我们主动保留）
2. AP 过程里只做：切栈 → 自旋读一个共享标志 → 看到标志才跳去干活
3. BSP：装轨 → ExitBootServices → 写标志 → 点火
```

**实测**：`StartupAllAPs` 一调，串口立刻出现并发交错（`[ ok ] yin ... hash 0x` 被 `[ ok ] cores 8` 从中间插断）—— **这就是多核真的在同时跑的物证**，单核上永远不会出现。

## 五、调度器：为什么发明了"算派"

### 传统调度的复杂度来自"可变状态"

runqueue 会被多个核改 → 要锁；任务状态会变 → 要原子操作；负载均衡要采样迁移 → 更复杂。

**算派的目标：把状态压到最小，决策全靠算。**

```
任务 = 不可变对象（因果 + 级别 + 入口 + 栈）
就绪 = 位图（64 位管 64 个任务），每 tick 发一份 COW 快照
分派 = 因果 & (核数-1)
时间片 = 12000μs × φ^级别
仲裁 = tick % 就绪数 → 位图上第几个置位
```

**全是纯函数，没有一处需要存状态。**

### 黄金比的实验（诚实记录：它输了）

原本想用 ⌊2⁶⁴/φ⌋ = `0x9E3779B97F4A7C15` 做乘法散列分派。实测：

| 场景 | 黄金比极差 | 取模/位与极差 |
|---|---|---|
| 连续名 `任务0..3999` | 35 | **7** |
| 纯随机 64 位 | 86 | **50** |
| 只变结尾 | 31 | **4** |

**三局全输。** 原因：FNV-1a 的低位分布本来就极好，乘法散列取高 3 位反而放大了偏差。

**结论**：核数是 2 的幂时，`h & (核数-1)` 一条 `and` 就够，比 `imul` 还快。

**φ 没浪费**，它用在了真正需要它的地方 —— 时间片衰减。

### φ 时间片：永不饿死的数学保证

```
级 0 → 12000 μs      级 5 → 1081 μs
级 1 →  7416 μs      级 6 →  668 μs
级 2 →  4583 μs      级 7 →  412 μs
级 3 →  2832 μs      级 8 →  254 μs
级 4 →  1750 μs      级 9 →  156 μs
```

相邻级别按 φ（0.618）递减，**几何级数收敛（总和 ≈ 31.4 ms）但每一项都 > 0** —— 低优先级永远拿得到 CPU，只是越来越少。

**踩坑**：一开始用毫秒做单位，级 5 之后全变 0（整数截断吃光小数）。**必须用微秒**。

定点实现（无 FPU）：

```
片 = (片 × 0x9E38) >> 16        // 0x9E38 / 65536 = 0.618
```

## 六、五行调度：五态比三态多在哪

传统三态：READY / RUNNING / BLOCKED。

五行五态：

| 五行 | 形态 | 含义 | 比三态多的信息 |
|---|---|---|---|
| 木 | 生 | 就绪 | — |
| 火 | 行 | 运行 | — |
| **土** | 载 | 等资源 | **分得清"等 IO"和"等锁"** |
| **金** | 收 | 收尾中 | **资源正在释放，别人不许抢** |
| 水 | 藏 | 休眠/后台 | — |

**相生相克的数学本质极干净：**

```
相生 = (态 + 1) % 5      下一个推下一个
相克 = (态 + 2) % 5      隔一个克一个
```

验算：木0→火1→土2→金3→水4→木0 是 `+1`；木0克土2、火1克金3 是 `+2` ✓

**所以整个状态机和约束体系，两行取模就定义完了。**

- **相生** = 状态机（任务该怎么走，deterministic）
- **相克** = 不变量（什么不能同时发生，invariant）

传统调度器把这两个混在 `if-else` 里散得到处都是，五行把它们分成两张表。

## 七、完整的踩坑表（写代码前必看）

| # | 症状 | 根因 | 修法 |
|---|---|---|---|
| 1 | `mov eax, 符号` 读到垃圾 | GNU as intel 语法里符号是**内存操作数** | 取地址一律 `offset 符号` |
| 2 | 一开分页就三重故障 | CR3 被写成了页表**内容**（0x101003） | 同上 |
| 3 | `LocateProtocol` 返回 INVALID_PARAMETER | **它没有 This 参数** | `RCX=Guid, RDX=Reg, R8=&Interface` |
| 4 | 内核一进 `#UD` | `原语.asm` 是 `.code32`，`pushad` 在长模式下非法 | 整份重写 `.code64` |
| 5 | `AllocatePages` 拿不到固定地址 | 枚举写错：`AllocateAddress = 2` 不是 1 | 且 MemoryType 用 `EfiLoaderCode(1)`，Data 是 NX |
| 6 | 入口跳到道标上 | 忘了道标占 64 字节 | `入口 = 落址 + 64 + 偏移` |
| 7 | `#PF @ 3MB` | **UEFI 页表只映射到 2MB** | 落址一律 < `0x200000` |
| 8 | 字符串全空 | `objcopy --only-section=.text` 丢了 `.rodata` | `-j .text -j .rodata -j .data` |
| 9 | 入口差 8 字节 | `AllocatePages` 失败拿到非页对齐地址 | 跳过分配，直接铺固定地址 |
| 10 | 内核在固件栈上跑 | Exit 后没设自己的栈 | 跳转前 `mov rsp, 0x70000` |
| 11 | `rdmsr 0x1A2` 崩 #GP | KVM 下该 MSR 不无条件可读 | 先 CPUID leaf 6 查支持，或干脆不读 |
| 12 | CPU 报 `AuthenticAMD` | QEMU 默认 `qemu64` 模型冒充 AMD | 测试必须 `-enable-kvm -cpu host` |
| 13 | 主链在 MP 之后断 | `GetNumberOfProcessors` 疑似破坏 rbx | 待查（已摘除） |
| 14 | `pkill -f qemu` 杀掉自己 | 命令行含该串，匹配到执行者 | 分两步或加参数区分 |

### 六爻语言自己的坑

| # | 症状 | 修法 |
|---|---|---|
| 1 | 报"期望 ')'" | 嵌套括号要数层数：`zt 存 01 态 , 01 v0 hr b0 02 02`（两层 02） |
| 2 | 报"声明必须跟一个名字" | 标识符至少两字符，`tt t` 不行，用 `tt tu` |
| 3 | 报"hs 后面必须是函数名" | 其实是"tt 后面不是标识符"—— 函数名 **不能与 64 条指令重名**（`hd`、`zr` 都是关键字） |
| 4 | 主函数不执行 | **lyc 按定义顺序生成代码**，主函数要放最前面 |
| 5 | 字符串里出现 04 就断 | 04 是单引号编码，写 `03…03` 同类开合 |
| 6 | `rdmsr` 报"名字不存在" | 不是内建，要读 MSR 得用汇编 |

## 十、一句话总结

**学原理，不抄形式。**

- 学 DWM 的"离屏面 + 合成"，不抄 COM / 句柄 / 注册表
- 学 UEFI 的"一次就绪"，不抄它的 AcpiTable / Protocol 套娃
- 学 Linux 的 console 分层，不抄它的 tty 子系统
- 六爻对应二进制是《易经》本来的结构（莱布尼茨 1703 已证），**混沌只是继承**：沿用八卦位序、六十四卦卦名，把 64 条指令顺着卦盘排下来
