────────────────────────────────────────────────────────────────
零、"自己编译自己"到底指什么
────────────────────────────────────────────────────────────────

  不是"程序会自我复制"，而是这条链：

    stage0   用 C 写的编译器 ──clang──► xyc            【已完成】
       │
       ├─ 用 xyc 编译「用新语写的编译器」──► stage1
       │
       └─ 用 stage1 编译它自己的源码 ────► stage2
                        ↓
              验收：hash(stage1) == hash(stage2)

  为什么 hash 相等就算成功：
    stage2 == stage1 意味着**新语写的编译器能完整复现自己**。
    从此这门语言不再依赖 C，可以自己进化。
    而且——本系统的世界观让"可信构建"变成白送的能力：
    哈希相等就是证据，不需要额外工具。

  最硬的一步是 M6：
    **把 xyc.c 从仓库删掉，只留 .xy 源码，项目仍能重建。**
    这一步过了，"从零"才闭环。

────────────────────────────────────────────────────────────────
一、自举门槛：语言必须能表达"编译器"
────────────────────────────────────────────────────────────────

  编译器干四件事，逐项对照我们缺什么：

    编译器要做的事                需要语言提供            现状
    ────────────────────────────────────────────────────────────
    词法：扫描字符串、查状态表    指针/字节读写/定长数组  ✅ 已有
    语法：建语法树、符号表        **结构体**               ❌ 缺
    语义：查表、比较名字          **字符串比较/常量表**    ⚠️ 缺
    代码生成：拼输出、格式化数字  整数/位运算/取余         ✅ 已有

  ── 必须补的两样 ────────────────────────────────────────────

    1. jg 结构体
       现在编译器内部用"平行数组"（vars[] / globals[] / toks[]）硬凑。
       能表达，但 stage1 会难写十倍。
       结构体让"一个 Token 是一个东西"变成语言事实。

    2. 字符串比较与常量表
       现在只能用字符循环手写比较。
       需要：内建 串比较（如 串同(a, b)）或 内建 字符串相等运算符。
       另外需要整数常量表（关键字表、类型表、优先级表）。

────────────────────────────────────────────────────────────────
二、里程碑（每步一个可验证的验收）
────────────────────────────────────────────────────────────────

  M1  语言补结构体 jg
      验收：用结构体实现一个符号表程序，能插入/查找/遍历，输出正确

  M2  按类型宽度解引用（*u32 一次读 4 字节）
      验收：通过指针读写 32 位整数，结果正确

  M3  让 stage1 能在"无文件系统"的环境下工作（关键取舍，见第三节）
      验收：stage1 读内嵌数组、把结果从串口吐出，宿主保存成文件

  M4  用新语实现 stage1 的词法部分
      验收：stage0 与 stage1 对同一输入产出**完全相同的汇编**
            （diff 两个 .s，零差异）

  M5  stage1 补完语法与代码生成，直到它能编译自己
      验收：hash(stage1) == hash(stage2)

  M6  删掉 xyc.c，仅用 .xy 源码重建
      验收：在没有 C 编译器参与的情况下，项目可重建

────────────────────────────────────────────────────────────────
三、关键取舍：编译器要读写文件，但系统还没有文件系统
────────────────────────────────────────────────────────────────

  问题：编译器必须读源码、写结果。而当前系统只做到"串口输出"。

  ── 路线甲（推荐）：输入内嵌，输出走串口 ───────────────────

      把 stage1 源码 + 待编译源码，都作为**编译期数据嵌进内核镜像**
      stage1 运行时：读内存数组 → 编译 → 结果从串口吐出
      宿主（QEMU）把串口输出重定向成文件

      优点：
        · 不需要文件系统、不需要存储、不需要系统调用
        · **第一版自举马上能跑起来**
        · 与内核开发解耦，风险最小

  ── 路线乙：等系统内核做到能读写存储，再自举 ───────────────

      更"正统"，但把自举和内核开发绑在一起。
      我们前面核查的三个项目，全都栽在"想一步做完"上。

  ── 裁定：采路线甲 ────────────────────────────────────────

      先把"自己编译自己"做成，**再**让系统长存储。
      这样任何时刻都存在一份"能跑的自举证据"，不会因为内核重构而丢失。

────────────────────────────────────────────────────────────────
四、隐藏要求：编译器输出必须确定性
────────────────────────────────────────────────────────────────

  自举要比对哈希，所以编译器输出**只能依赖输入**。禁止：

    ✗ 哈希表遍历顺序不稳定（会让符号输出顺序漂移）
    ✗ 嵌入时间戳、源码路径、随机数
    ✗ 依赖并行导致的不确定顺序

  从现在起立一条规矩：

      编译器的输出 = f(输入源码)
      不包含任何环境信息。

  这条规矩现在写下来，将来省一大堆事。
  （对照断言 A16：同源码 + 同编译器 → 输出哈希相同）

────────────────────────────────────────────────────────────────
五、让"自举"变成可自动验证的东西
────────────────────────────────────────────────────────────────

  自举最容易变成"口头宣称"。所以必须做成命令：

    # 1. stage0 编 stage1
    ./xyc 编译器.xy -o stage1.s && as/ld → stage1.elf

    # 2. stage1 编自己
    ./stage1 编译器.xy -o stage2.s

    # 3. 比对
    cmp stage1.s stage2.s || echo "自举失败"

  ★ 注意这里比对的是**汇编文本**而不是二进制 ——
    因为 elf 头里可能有构建时间等无关差异，
    比对编译器真正的产出（汇编）更严格也更干净。

  验收断言（接 A1–A54）：
    A55 [自举]      stage1 与 stage2 的汇编输出逐字节相同
    A56 [确定性]    同一输入连续编译两次，输出相同
    A57 [无宿主]    删除 xyc.c 后，项目仍可仅凭 .xy 源码重建
    A58 [子集闭合]  stage1 能编译"stage1 自身用到的全部语法"

────────────────────────────────────────────────────────────────
六、完成之后是什么样
────────────────────────────────────────────────────────────────

  自举成功那天，你得到的不是"一个能跑的编译器"，而是：

    1. 一门**完整的语言**（能表达自己的实现）
    2. 一条**可验证的构建链**（哈希相等即证据）
    3. 一个**能自己长大**的东西（以后加特性只需改 .xy）

  然后才轮到下一层：把编译器搬进系统（自举三件套之一），
  与对象存储、视图、能力模型合体 —— 那才是"完整的系统"。

  顺序不能反：
      语言先自举 → 系统再自带 → 最后系统自重建（A23）
